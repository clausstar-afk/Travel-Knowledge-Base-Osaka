# 🍄 旅圖知情所｜Travel Knowledge Base

大阪自由行行程規劃網頁，整合景點資料庫、航班／天氣查詢、AI 語意搜尋與客製化行程建議，並提供拖拉分天、匯出（表格／Markdown／iCal／分享連結）等實用工具，協助自由行旅人從「找景點」到「排好整趟行程」一站完成。

網頁內建 AI 助理角色 **Kinopio 🍄**，負責語意搜尋景點與撰寫有溫度的行程介紹——原則上 AI 只負責「寫感受、給建議」這類主觀內容，所有時間、價格、營業時間等事實性資訊一律來自實際資料源（Google Sheet／官方 API），避免 AI 對關鍵決策資訊產生幻覺。

專案為純前端靜態網頁（單一 HTML 檔，內嵌 CSS／JS），沒有自架後端伺服器，資料來源與運算全部發生在瀏覽器端與第三方 API 之間。

## 主要功能

### 景點瀏覽與搜尋
- 從 Google Sheet 動態讀取景點資料庫（CSV 發布網址），含營業時間、門票、交通、推薦理由等完整欄位
- 分類篩選 Chips、關鍵字即時篩選
- **Kinopio AI 語意搜尋**：用自然語言描述想要的景點（例如「適合下雨天的室內景點」），由 Kinopio 依語意排序回傳結果
- 桌面版最多 4 欄卡片網格，卡片精簡設計兼顧資訊密度與可讀性

### 航班與環境資訊
- 輸入航班號碼＋日期查詢實際起降時間（AeroDataBox API），自動加進行程開頭（去程）或結尾（回程）
- 防呆：非大阪機場（關西／伊丹／神戶）不會誤植入行程；去程／回程日期互相牽制不可矛盾
- 查到去程日期後自動查詢大阪天氣預報（Open-Meteo，未來 16 天）與每日日落時間（sunrise-sunset.org）
- 「我的行程」時間軸的航班卡片提供「查看機位配置圖」連結（去程／回程各自獨立），依航班號碼自動導向 [AeroLOPA](https://www.aerolopa.com/) 對應航空公司頁面——放在時間軸卡片而非查詢結果訊息，是因為卡片同時顯示機型，才知道該對照哪個機型的座位圖
- 航班號碼輸入框提供自訂樣式的自動完成建議（AeroDataBox 航班號碼搜尋），減少手打航班號碼漏字/格式錯誤導致查詢失敗
- 航班號碼＋日期都填好後，自動比對這個航班號實際排班的日期，選到「這天沒有排班」的日期會即時警示提醒（原生日期選擇器沒辦法把個別日期反灰，改用選完立刻檢查提示的做法）

### 手動排程行程表
- 自訂總天數，拖曳（或手機版按鈕）把景點排入指定天數與順序
- 本地即時運算每個景點的預估時段（零 API 成本），並用「區域距離啟發式」估算站點間交通時間
- 相鄰兩個景點之間提供「🔍 查看交通方式」連結，直接開 Google 地圖幫忙查好轉乘路線（免金鑰、免額外 API 呼叫，用地名直接組出地圖路線網址）
- 自動偵測：景點可能的定休日、預估時段可能超出營業時間、營業時間欄位裡的「最終入場／L.O.」資訊
- 雨天室內備案標記：這天預報有雨時，自動標示哪些已排入的景點適合當雨天備案
- Day 1 出發時間自動考慮航班抵達時間＋緩衝

### Kinopio AI 客製化行程介紹
- 依使用者輸入的旅遊風格（親子／美食控／慢步調⋯）與已排定的天氣資訊，生成行程開場白、每日小語、天氣提醒與打包建議
- 行程內容有變動時會自動提示「介紹已過期，可重新生成」

### 🍄 Kinopio 聊天問答（實驗性功能）
- 右下角浮動按鈕，帶有柔和流動的模糊光暈（呼應「精靈」的靈巧感），按鈕底色加深以襯托光暈；單擊開啟聊天面板，可針對旅遊相關問題自由提問，串接 OpenRouter 的免費模型
- **雙模型備援**：主要模型（Gemma 4 26B A4B，速度快）失敗時自動改打備援模型（Gemma 4 31B）再試一次，使用者不會感覺到中間切換過模型，兩個都失敗才會看到錯誤訊息
- 系統提示詞限制回答範圍在旅遊規劃相關主題，遇到精確的營業時間/價格等事實性資訊會提醒使用者以官方公告為準，不武斷給數字；並即時從景點資料庫抓取分類清單限制推薦範圍、明確禁止 AI 提議「幫你加入行程表」這類實際上做不到的動作
- 對話歷史只保留最近幾輪，避免單次呼叫內容量無限累加；額度用完（HTTP 429）會顯示友善提示，不會讓畫面卡住
- ⚠️ **目前狀態**：程式邏輯與 UI 已完整測試（含雙模型備援切換、XSS 防護、額度用完提示），但真實情境下發現主要模型（26B A4B）目前經常回傳 429（推測是該免費模型當下全球需求量大），加上備援模型後尚未實際驗證備援是否能穩定接手，之後需要再找時間確認

### 匯出與備份
- 匯出 Modal：表格預覽（同天自動合併儲存格）、**「下載行程表」一鍵選擇 Markdown（.md）／CSV（.csv，可用 Excel 或 Google 試算表開啟）／行事曆（.ics，含每站預估時段，可直接匯入手機行事曆）三種檔案格式下載**、複製表格 Markdown 文字、**產生分享連結**（免登入、免後端，把行程狀態編碼進網址分享給同行者）
- 行前準備清單：常見出國物品勾選清單，狀態本機保存

### 帳號與資料
- Google 登入（僅用於顯示大頭貼／名稱）
- 行程、分天計畫、行前清單皆依登入帳號分開儲存（未登入視為訪客身分），不同帳號登入不會看到彼此的資料

### 響應式設計
- 手機／平板／桌面斷點齊全，頁籤與搜尋列在捲動瀏覽景點時會黏性固定在頂部

## 網頁價值與解決痛點

自由行規劃最大的痛點，是資訊分散在太多地方：景點清單、營業時間、航班、天氣、交通時間、公休日⋯要一個個分頭查，最後還要自己拼成一份可執行的行程表。這個專案想解決的具體問題：

- **時間對不上的風險**：手動排行程常常沒注意到某景點公休、或排的時段已經打烊，這裡用資料欄位自動比對，排錯的機率降低
- **交通規劃曠日廢時**：用區域距離估算銜接時間，取代「隨便抓 30 分鐘」的猜測；相鄰景點之間再提供一鍵「查看交通方式」連結，省去自己一站一站開地圖查轉乘的時間
- **航班與行程脫節**：查完機票時間常常要自己回頭調整 Day 1 行程，這裡自動用航班抵達時間反推合理出發時間
- **天氣是規劃行程時最容易被忽略的變數**：抵達日期一確定就自動查天氣，雨天景點自動標示室內備案
- **AI 建議必須守住事實邊界**：讓 AI 負責寫「有溫度的文字」而不是負責「決定事實」，降低 AI 幻覺誤導使用者行程規劃的風險
- **行程只存在自己腦中或聊天記錄裡**：提供表格／Markdown／iCal／分享連結多種匯出方式，行程可以真正被帶著走、分享給同行者
